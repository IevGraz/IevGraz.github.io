**Why I read this book:** I moved from Backend Engineer to Site Reliability Engineer because I always felt I didn't understand enough about the technical limits of running software (what resources it can run out of, and why). In the new role, I found myself following runbooks that dealt with device mapper and systemctl without understanding what those tools actually are. So I decided to learn more about Linux. It took me a year and a half to get through the book, so I no longer remember why I picked this one in particular.

**What I liked about it:**

It did fill in the gaps I started with. It has whole chapters on devices, filesystems, and systemd. I read the first two around the same time I was writing test code that created partitions and logical volumes. The timing was great. I got to learn those concepts and how they relate to each other.
Most chapters have a point where the author says, "If this is your first time through, skip to the next chapter and start learning about XYZ." I took this advice very eagerly, as there was already a lot of new and not-so-easy information to process.

**What I disliked:**

The first nine chapters were the most interesting for me. Once I reached the networking chapters, I really started to struggle. They felt too far removed from any work I've ever done. I think they're the reason it took me so long to finish the book. Some of the final chapters, like the introduction to shell scripting, the Linux desktop, and printers, felt completely irrelevant to me. The shell scripting one would probably have been useful before AI tools got so good. If you do want to get better at the command line, I'd point you to [Efficient Linux at the Command Line](/book_reviews/efficient_linux.html) instead.

The author doesn't always explain things in the clearest way. At some point I started sending screenshots of the paragraphs I struggled with most to an AI. It gave me much simpler explanations.

Overall, finishing the book felt a bit anticlimactic. I had hoped that I would read it, take notes, go through those notes, and a lot of things would click into place. Instead, my notes were mostly surface-level, basic explanations. One review I came across summed up my feelings well: "Too deep for an introduction, too shallow for a manual."

Still, if you're in a similar position to mine and not too familiar with Linux, it's a good book to pick up. Just don't force yourself to read it cover to cover. Focus on the chapters that seem interesting or useful to you, and skip the rest.
